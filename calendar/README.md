# ショートステイ・体験利用 管理表 v5

`dist/ショートステイ管理表_v5.html` を**ダブルクリックで開くだけ**で動きます。
サーバーもインターネット接続も不要です（フォントとReactはファイル内に同梱）。

データは開いたブラウザの localStorage に自動保存されます。旧版（v4）で入力済みの
データがある場合は、初回起動時に自動で引き継がれます。

---

## v4 からの変更点

### 不具合の修正

| 内容 |
|---|
| 初期表示月が `2026-08` で固定されていた。今月を開くようにした |
| 利用者マスタの氏名を直しても既存の予約記録に反映されなかった（区分・送迎は反映されていた）。氏名にも反映するようにした |
| 滞在の入所↔退所の紐付けが「氏名＋部屋」だったため、滞在中の部屋替えや氏名修正で滞在が分断された。`stayId` で紐付けるようにした |
| 重複予約が保存時にブロックされるだけで、復元データや旧形式で入り込んだ重複は画面上どこにも出なかった。カレンダーに警告バッジと件数バナーを出すようにした |
| 稼働率の定義がカード上に出ていなかった。「延べ利用日数 ÷ 室日」であることを明示した（値の内訳も併記） |
| 送迎あり件数が入所・退所の2レコードを別々に数えて倍になっていた。滞在単位に修正した |

### 追加した機能

- **タイムライン表示**（部屋 × 日のガント）。連泊が1本の帯で見える。
  - 帯をドラッグ＝日程移動 / 帯の左右の端をドラッグ＝入所日・退所日の変更 /
    空きトラックをドラッグ＝その期間で新規予約
  - 移動先が重複する場合は移動を取り消して理由を表示
- **空室照会**。期間を入れると空いている部屋を返す。そのまま予約作成へ進める
- **当日の動き**。入所・退所・滞在中・送迎予定と、**食数（朝/昼/夕）の合計**
- **カレンダー上の食事バッジ**。各マスの下に `朝` `昼` `夕` を並べ、**必要な食事だけ色を付ける**。
  **バッジをクリックするとその場であり/なしを切り替え**られます（滞在者が複数いる日はまとめて切替）
  （朝＝橙・昼＝緑・夕＝紫）。位置が固定なので縦に流し読みでき、「この日は夕食だけ」が
  一目で分かる。2名以上の食事は `昼2` のように人数が付く。滞在者が居る日は食事0でも
  バッジ行を出す（「誰も居ない日」と「居るが食事なしの日」を区別するため）
- **一覧・印刷**表示。月内の利用を明細表で一覧・印刷
- **食事の日別管理**。初日は夕食から、最終日は朝食まで、中日は3食、を既定値として
  日ごとに編集できる（v4 は1滞在に朝昼夕の3フラグしか持てなかった）
- **CSV書き出し** 3種（明細 / 区分別集計 / 食数）。BOM付きUTF-8でExcelがそのまま開ける
- **仮予約・調整中の視覚的区別**（破線表示）と、集計に含めるかの切替
- 月ナビゲーションを「◀ 前月 / 月ピッカー / 翌月 ▶ / 今日」に変更（v4 は18個の横スクロールタブ）
- 「今日」バッジ、備考のツールチップ、標準入所・退所時刻のマスタ化、延泊/短縮ボタン
- スマホ表示対応（月グリッドを1列に、当月以外のセルを非表示）
- 記録ごとの最終更新日時・更新者、および**別端末のバックアップのマージ取り込み**

#### 支給量（受給者証の月あたり上限日数）

利用者マスタに **支給量（日/月）** を登録すると、超過を事前に知らせます。空欄なら管理しません。

- **予約を作るとき**にドロワーへ「2026年8月 5 / 7日　残り 2日」と出ます。超える場合は
  赤く「支給量を N日 超えます」と表示します。**保存は止めません**（緊急利用など、
  正当に超える場面があるため）
- 期間が月をまたぐ予約は、**かかる月それぞれ**で判定します
- 「利用者数」カードを開くと、利用者ごとに使用日数・残り日数が出ます
- 区分マスタの「**支給量に含める**」で、区分ごとに数える/数えないを切り替えられます
  （既定は全て「含める」。取りこぼして超過に気づかないより、多めに数える方が安全）
- 日数は**日付の集合**で数えるため、同じ日に複数の記録があっても1日と数えます

#### 定期利用の一括登録

「定期予約をまとめて作成」から、**毎週／隔週／毎月第◯週**の定期利用を期間指定で
一度に登録できます。

- 曜日は複数選択可。1回あたりの泊数・入退所時刻・部屋・区分・予約状態を指定
- **作成前にプレビュー**が出ます。すでに予約が入っている日は自動でスキップし、
  理由（部屋の重複／同じ方の予約と重複）を一覧に表示します

#### 稼働率の数え方

**稼働率 = 延べ利用日数 ÷ （月の日数 × 部屋数）** です。請求実績が利用日単位で
数えられるため、突合しやすいこちらを採っています。

利用日は退所日を含みます。そのため同日入替（朝に退所 → 夕方に次の方が入所）が
あった日は 1 室が 2 人ぶん数えられ、月によっては 100% を超えます。数え方どおりの
挙動なので値は丸めていません。カード下段に「延べN利用日 ÷ M室日」と内訳を
出しているので、超えた理由はその場で確認できます。

なお「延べ宿泊数」（退所日を含まない数え方）も別途出しており、期間指定レポートの
カードと明細CSVで確認できます。部屋の重複判定・空室判定にはこちらを使っています。

### 印刷（表示ごとに用紙が自動で決まります）

印刷ダイアログで毎回設定する必要はありません。表示中のタブに応じて、用紙の向きと
中身が自動で切り替わります。

| 表示 | 出力 |
|---|---|
| **月カレンダー** | **A4横・1枚。そのまま現場に貼れる壁掛けカレンダー** |
| 一覧・印刷 | A4縦。利用明細の一覧表 |
| FAX作成 | A4縦。FAX用紙（送信状を付ければ2枚） |

月カレンダーの印刷では、画面用の部品（KPI・タブ・ボタン・警告バナー）は一切出ず、
**年月と施設名の見出し＋カレンダーの枠＋凡例だけ**になります。マスの中身は
部屋ごとの利用者名・入退所時刻・送迎・食数で、空室は「空」と出ます。

紙面は**印刷ダイアログの「背景のグラフィック」がオフのまま**でも読めるように
作ってあります（この設定は既定でオフのため）。白黒プリンタでも本文が黒く出ます。

### FAX作成（空き状況カレンダー）

ビュータブ「FAX作成」から、その月の空き状況をA4のFAX用紙として出力できます。
**予約を変更すると紙面も自動で変わります**（別途の転記作業は不要）。

カレンダーの各マスは、予約状況から自動で4状態に振り分けられます。

| 表示 | 意味 |
|---|---|
| `OK` | 全室空き |
| `残N` | 一部空き（N室残り） |
| **黒ベタ + 白抜き×** | 満室 |
| 太枠 + `仮` | 空きは無いが、埋めているのが仮予約・調整中のみ |

- **各マスは「その日の夜（宿泊）」の空き**を表します。退所日の当日は次の方が入れるため空き扱いです
- 利用者名は一切載りません（誤送信時の被害を無くすため）
- 宛先はFAX送付先マスタから選択。番号を都度手入力しないので誤送信を防げます
- 送信状（カバーシート）を任意で1枚目に付けられます。枚数は自動計算
- 印刷時はアプリのUIを全て除き、この紙面だけがA4縦で出ます

FAXは白黒2値・200×100dpiで、淡い塗りや細い色文字は再現されません。そのため
この紙面だけは色を使わず、黒ベタ・太罫線・大きな文字だけで組んでいます。

### FAX帳票用のマスタ

- **施設連絡先**: 郵便番号 / 住所 / 電話 / FAX / 担当者名 — 帳票のヘッダーと送信状に印字する送信元
- **FAX送付先マスタ**: 事業所名 / 担当者 / FAX番号 / 電話 / 備考
- **定型文**: 持ち物 / 注意事項 — 予約確認書に差し込む（予約確認書自体は未実装）

### 複数施設での利用（施設ごとにデータを分離）

ヘッダーの「**施設を切替**」から、1つのファイルで複数の施設ぶんを、
**互いに独立して**管理できます。片方を編集しても、もう片方には一切影響しません。

#### なぜこれが必要か

`file://` で開いたページの localStorage は「**ファイルごと**」ではなく
「**`file://` 全体でひとつ**」です。そのため HTML をコピーしてフォルダを分けても、
同じPC・同じブラウザで開けば**同じ保存領域を共有してしまい**、施設Aの更新が
施設Bのファイルにも現れます。ファイル名やフォルダを変えても解決しません。

実測（Chromium）:

```
facA/kanri.html で施設名を「施設A」に変更
  → facB/kanri.html を開くと …… 施設A と表示された
```

そこで保存キーを施設ごとに分けました（`ss-kanri-v2::<施設ID>`）。

#### 使い方

- 「施設を切替」→「＋ 施設を追加」で施設を増やします
- 「＋ 今の設定を引き継いで追加」は、部屋・区分・送迎・FAX送付先などの**設定だけ**を
  コピーします（予約データは引き継ぎません）
- 施設名はマスタ設定で変更でき、切替一覧のラベルも自動で追従します
- **ショートカットで施設を固定できます。** URL の末尾に `#site=<施設ID>` を付けると、
  開いた瞬間その施設になります。IDは切替画面に表示されています。
  施設ごとにデスクトップショートカットを作っておけば、切替忘れによる
  他施設への誤入力を防げます
- バックアップは「表示中の施設のみ」（マスタ設定）と
  「**全施設まとめて**」（切替画面）の2種類。全施設バックアップのファイルを
  復元すると、施設一覧ごと差し替わります

既存の（施設分離より前の）データは、初回起動時に自動で最初の施設へ引き継がれます。

### 実装していないもの

- **複数端末でのリアルタイム共有**。サーバーが必要なため、単一HTMLでは実現できません。
  上記の施設分離は「1台の端末の中で施設ごとにデータを分ける」機能であって、
  端末間の同期ではありません。別端末へ渡すには
  「バックアップ保存 →(共有フォルダ等)→ 別端末で"取り込む（マージ）"」を使ってください
  （同一予約は更新日時が新しい方を採用）。

## 開発

```
node build.mjs
```

`src/template.html`（画面）と `src/logic.js`（ロジック）を、配布用の単一HTMLへ
組み立てます。フォントとReactランタイムは既存の成果物から引き継ぐため、
`dist/` の中身を消してしまうと素材元が無くなりビルドできません。その場合は
元の v4 ファイルを `assets/base-bundle-v4.html` に置いてください。

`src/` はこのプロジェクト独自のテンプレート言語（`sc-for` / `sc-if` /
`sc-camel-on-*` / `{{ }}`）で書かれています。注意点:

- イベントは `sc-camel-on-click` のようにケバブケースで書く（HTMLパーサが属性名を
  小文字化するため、`onClick` は使えない）
- `<table>` 系は `<sc-raw-table>` `<sc-raw-tr>` … を使う。素の `<table>` の中に
  `<sc-for>` を置くと、HTMLのテーブル解析規則で外へ追い出されて行が壊れる
- `{{ }}` の中身は `<span class="sc-interp">` に包まれて出力される。
  `.foo span { color: ... }` のような一括指定をすると、親から継承させたい色を
  その内側spanが上書きしてしまう（FAX紙面の白抜き文字が黒地に黒で消えた）
