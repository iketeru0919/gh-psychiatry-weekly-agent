# RASIEL 営業活動報告チャットの拠点別集計 — 提案とリファレンス実装

## 背景・課題

各拠点の管理者は、LINEの営業活動報告チャットに毎日ほぼ決まった項目（①名前 ②拠点名 ③入居者数
…⑨カメラ録画確認、夕方は⑤短期稼働日数〜⑬入居＋【翌日の予定】）を投稿している。この内容を
拠点ごとに手作業で拾って集計すると、AM側の工数が増えてしまう。

要望は次の3点。

1. 管理者側の入力の手間を増やさず、今書いているチャット報告をそのままデータソースにしたい
2. 日次・週次でAMがタイムリーに実績集計できるようにしたい
3. できればAIを使わず、オフラインでも動く方法にしたい

## 結論（提案）

**正規表現とラベル辞書によるルールベースの抽出**で十分実用になる。実際に今回いただいたログ
（7/20〜7/23、207メッセージ）を試作パーサーに通したところ、**207件全メッセージ・42拠点すべて
で拠点名を正しく抽出**できた（詳細は「検証結果」を参照）。AI/外部APIは一切使わず、ネットワーク
接続も不要。

成果物を2つ用意した。

| 成果物 | 用途 |
|---|---|
| `tools/rasiel_report_tool.html` | ブラウザで開いてログを貼り付けるだけで使える単一HTMLツール。AM各自がすぐ使える。 |
| `src/rasiel_facility_reports/` (Pythonモジュール) | CSVパイプライン化・自動集計・CIでの定期実行など、システム化する場合の土台。 |

どちらも同じ抽出ロジック（丸数字→ラベル辞書→正規化）で、AI/外部APIには依存しない。

## 抽出方式の仕組み

1. **メッセージ分割**: チャットのコピペテキストは「タイムスタンプが次メッセージの先頭に連結
   される」形式になっている（例: `…⑨カメラ録画確認：〇1\n7月20日 7:27三畦　拓也…`）。行頭の
   日付・時刻トークンを剥がした残りが `[To:` を含む、または「さん」で終わる場合だけを
   メッセージの境目と判定する。これにより【翌日の予定】欄に書かれた `9:30~ PDCA面談` のような
   本文中の時刻表記を誤って区切ってしまう問題を回避している。
2. **項目抽出**: `①`〜`⑭`（`①②③…`系と`➀➁➂…`系の両方の丸数字表記に対応）の直後にある
   ラベル文字列（「名前」「拠点名」「短期稼働日数」など）をラベル辞書と照合し、丸数字の
   **位置（何番目か）ではなくラベル文字列そのもの**をキーに正規化する。朝報告
   （⑤営業予定時間〜⑨カメラ録画確認）と夕方報告（⑤短期稼働日数〜⑬入居＋【翌日の予定】）で
   項目の並び・個数が違っても、ラベル一致なので同じ処理で吸収できる。
3. **拠点名の正規化**: 「RASIEL南志賀」「南志賀」「株式会社ラシエル(南志賀・管理者)」のような
   表記ゆれは、"RASIEL" "ラシエル" "株式会社ラシエル" "・管理者" 等のノイズ語を機械的に除去して
   同一キーに寄せている。
4. **日次マージ**: 同一拠点・同一日に複数回投稿（朝→夕方の更新）がある場合は、その日の最後の
   値で1行にマージする。朝にしかない項目（カメラ録画確認・預り金管理）と夕方にしかない項目
   （問合せ件数〜入居）は両方保持される。
5. **週次・月次集計**: 問合せ件数・案件発掘・見学・体験・仮申込・入居・営業予定時間・営業実績
   時間は期間内の**合計**、入居者数・目標入居件数・短期稼働日数・営業累計時間・営業実績件数
   累計はすでに月内累計の値なので期間内の**最終報告値**を採用する（合算しない）。

## 追加機能（依頼を踏まえて実装）

- **拠点フィルタ**: 担当拠点リストをブラウザに保存しておき、既定で絞り込み表示。加えて
  その場限りのキーワード検索でも絞り込める（保存はされない）。CLI版は `--facility` を複数指定。
- **表示項目のカスタマイズ**: チェックボックスで列の表示/非表示を切り替え、選択状態は保存
  される。CLI版は `--fields occupancy,inquiries,tours` のようにカンマ指定。
- **週次・月次サマリー**: ISO週 or 月単位でロールアップするタブを用意。
- **未報告拠点チェック**: これまで一度でも報告のあった拠点のうち、指定日に報告が見つからない
  拠点を一覧表示。抜け漏れ管理・法令順守の観点で価値が高いと判断し優先実装した。
- **異常値ハイライト**: 「問合せ〜入居のファネル項目が全て0」「営業実績時間が0」の行を
  自動で色分け。上司報告時に「説明が必要な拠点」を先に把握できる。
- **未認識ラベルの可視化**: ラベル辞書に無い書き方（例: 「営業累計時間」を「営業累計時」と
  誤記した投稿）を件数付きで一覧表示。フォーマット改善のフィードバックに使える。

## 使い方

### HTMLツール（管理者・AMがすぐ使う場合）

`tools/rasiel_report_tool.html` をブラウザで開き、チャットログを貼り付けて「解析する」を押す
だけ。処理はすべてブラウザ内で完結し、外部送信は一切ない。設定（担当拠点リスト・表示列・
最後に貼り付けたログ）はこの端末のlocalStorageに保存され、次回開いたときも再現される。

「サンプルを読み込む」ボタンで簡易サンプルの動作確認ができる。

### Pythonモジュール（自動化・システム連携する場合）

```bash
PYTHONPATH=src python -m rasiel_facility_reports sample_data/rasiel_chat_sample.txt \
  --out-dir reports/rasiel \
  --default-year 2026 \
  --facility 南志賀 --facility 御所 \
  --fields occupancy,inquiries,tours,move_ins \
  --missing-on 2026-07-23
```

`reports/rasiel/raw_messages.csv`（1メッセージ1行の生データ）と
`reports/rasiel/daily_summary.csv`（拠点×日付でマージした日次サマリー）を出力する。

## 検証結果（今回いただいたサンプルログ）

- メッセージ件数: 207件（`sample_data/rasiel_chat_sample.txt`）
- 拠点名の抽出に失敗した件数: **0件**（全件で拠点名を特定できた）
- ラベル辞書に無い未認識ラベル: 2件（河野さんの投稿で「営業累計時間」が「営業累計時」と
  表記されていたケース。辞書に無い書き方は黙って捨てずに「未認識」として可視化される）
- 日次サマリー行数: 120行（拠点×日付の組み合わせ）
- テスト: `tests/test_rasiel_facility_reports.py`（`pip install pytest` 後に
  `python -m pytest tests/test_rasiel_facility_reports.py` で実行、9件すべて成功）

## 運用ルールとして提案したい微修正（案B: 管理者の負担を増やさない範囲）

抽出精度をさらに上げたい場合、以下程度の運用微修正を管理者へ依頼すると効果が大きい
（入力の手間は増えず、書き方を少し揃えるだけ）。

1. 丸数字は `①②③…` に統一する（`➀➁➂…` との混在をやめる）
2. 「該当なし」は空欄・「No.」・「なし」など表記がバラバラなので、できれば `0` に統一する
3. 「営業累計時間」のような固定ラベルの誤記（「営業累計時」等）に気づいたら直す
4. 拠点名は略称を1パターンに固定する（例: 「RASIEL南志賀」で統一、「南志賀」単独表記はやめる）

ただし、これらを待たずとも**現状のログのままで実用に足る精度**は出ている（表記ゆれは正規化・
ラベル辞書側で吸収済み）。

## 既知の限界

- チャットのコピペ形式に依存したメッセージ分割ロジックのため、コピー方法やLINE側の表示形式が
  変わると調整が必要になる可能性がある。
- 日付をまたぐ投稿（例: 20:33の投稿に翌日の日付区切りが連結されているケース）は、まれに日付の
  判定がずれることがある（今回のサンプルで1件確認）。
- 「入居」欄などに数値ではなく「〇〇様入居されました」といった文章が入る場合、週次・月次の
  合計では便宜的に「1件」として数える実装にしている。件数として厳密に数えたい場合は、
  管理者側で数値記載をお願いするのが最も確実。
- 空欄（未報告・未入力）と「0」（実績ゼロ）は意味が異なるはずだが、現状は区別せず両方とも
  空文字列として扱っている。区別が必要な場合は追加のルールを検討する。
