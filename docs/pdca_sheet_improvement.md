# 週間PDCAシート 改善提案

対象ファイル
- `PDCAシート（2608）.xlsx` … 1施設分のPDCA管理簿（週間PDCA＋月別シート22枚ほか）
- `施設担当一覧（住所追加版）.xlsx` … 40施設・担当AM 16名のマスタ

成果物
- `dist/週間PDCA_改善版テンプレート.xlsx` … 改善版テンプレート（施設マスタ内蔵）
- `tools/pdca/build_pdca_template.py` … 上記を再生成するスクリプト

---

## 1. 現行シートの構造

`週間PDCA` は1枚に第1〜第4週のブロックを横並び（A〜AI列、51列）で持ち、各ブロックが
`①施設稼働／②短期入所／③加算詳細／④訪看契約／⑤SQ利用` の5カテゴリ×3行（KGI・KPI・対応方針・所感）で構成されています。
右端の AL24:AY70 が隠れた集計エリアで、`HLOOKUP($I$1, $AN$24:$AY$63, n, 0)` により
I1セルの月名（例: `4月`）に対応する月シートの値を引いています。

## 2. 検出した不具合（数式レベル）

| # | 箇所 | 内容 | 影響 |
|---|---|---|---|
| 1 | `AE5` `AE7` `AE9` `AE11` | 第4週ブロックが第1週（`=D5` `=D7`…）を参照。第2→第3週は連鎖しているのに第4週だけ戻っている | 月末週の行動設定が第1週の焼き直しになり、改善サイクルが1周分失われる |
| 2 | `C17` | ④訪看契約のKPIだけ `='2月'!BF30` と特定月シートへ直リンク。他は `AM`列のHLOOKUP経由 | 対象月を切り替えても2月の値が出続ける |
| 3 | `AN65:AY65`（翌月稼働）ほか `AY66` `AY67` `AY68` `AY70` | 1列ずらし参照で、最終列が空の `AZ51` `AZ54` `AZ55` `AZ56` `AZ69` を見ている | 3月（年度末）の翌月稼働・リピート・予算比・前月比・平均利用回数が常に0 |
| 4 | `G1` | `=AM63+365`（月シートのN3日付＋365日）で第1週の基準日を作り、以降は+7の連鎖 | うるう年で1日ずれる。年度をまたぐと破綻し、日付の根拠も追えない |
| 5 | `AM25:AM64` | HLOOKUP表は12か月分の列（`AN24:AY24`）しか持たないが、実ファイルの月シートは22枚（`4月 `＝末尾スペース、`26年６月`、`26年７月 ` など） | 26年6月以降のシートは集計対象外。シート名の1文字修正で全参照が `#REF!` |
| 6 | `予算達成状況!B13:Y13` | 判定が `=IF(予算比>=0,"〇","✕")` の2値のみ。`B26` などに文字列 `-` が混在 | わずかな未達と大幅未達が同じ「✕」。文字列混在で平均・グラフが崩れる |

## 3. 構造・運用上の課題

1. **施設と担当者がファイル内に存在しない。** 週間PDCAには担当者列（F/O/X/AG）がありますが空欄・自由入力で、施設名はどこにもありません。識別子がファイル名だけなので、40施設を横断した比較も、担当AM別の遅延把握もできません。
2. **週が「列」なのでコピー構造に依存する。** 行の挿入・削除でブロックがずれ、第5週がある月に対応できません。
3. **PDCAの中身が長文テキスト。** `【営業行動】…▶2/25追客` のような改行入りの1セルに目標と実績と期日が混在し、達成／未達を数式で判定できません。
4. **ステータス・期限が機能していない。** 結合セルのまま空欄で、入力規則も条件付き書式もなく、期限超過が誰にも見えません。
5. **「※未対象施設」の行が毎週コピーされ続ける。** 対象外項目がノイズになり、対象化の判断者も決まっていません。
6. **`週間PDCA (見本)` が本体と別に存在し内容がずれている。** 書き方の基準が人によって変わります。
7. **`Sheet2` に居室番号・区分・年齢の生データが残置。** 配布時に意図しない情報が同梱されます。

## 4. 改善版テンプレートの構成

`dist/週間PDCA_改善版テンプレート.xlsx`

| シート | 役割 |
|---|---|
| `00_はじめに` | 設計の狙いと使う順番。黄色セルのみ入力可 |
| `01_施設マスタ` | 添付一覧の40施設。施設ID（F001〜F040）を主キーに付与し、`東 将学（尾方 範夫）` のような表記を「担当AM」「兼務・副担当」に分離。住所から都道府県を抽出。`PDCA対象` フラグ付き |
| `02_担当者マスタ` | 担当AM 16名。担当施設数・GH数・生活介護系数・担当エリアを自動集計 |
| `03_設定` | 対象施設（プルダウン）・年・月・第1週の基準日を1か所で指定。業種／指定権者／都道府県／担当AM／兼務／住所を自動表示。第1〜第5週の基準日を+7で自動採番 |
| `04_課題管理表` | 縦持ちの課題台帳。Plan/Do/Check/Actを列で分離し、KPI目標値・現状値・達成率を数値で保持。担当者・カテゴリ・ステータスはプルダウン、残日数と遅延判定は自動、遅延行は自動着色 |
| `05_週次KPIログ` | 週×指標の縦持ちログ（第1〜第5週×9指標を初期投入）。年・月・施設名・担当者を各行に持つため、40施設分を連結してもピボットで集計可能 |
| `06_ダッシュボード` | KPIの週次推移と月間達成率（率は週平均、件数は合計）、〇/△/✕の3段階判定、課題ステータス集計、担当AM別の課題件数・遅延件数 |
| `07_改善提案一覧` | 上記の不具合・課題15件を「現状／リスク／改善案／本テンプレートでの対応／優先度」で一覧化 |
| `08_運用ルール` | 週次・月次の担当と判断基準の案 |
| `09_リスト` | プルダウン用マスタ（非表示） |
| `10_月次_GH稼働` | 利用者×日（1〜31日）の稼働カレンダー。●=稼働／入=入院／外=外泊。日別合計行から週別の稼働回数・稼働率・入院・外泊を自動集計 |
| `11_月次_SS稼働` | 短期入所の利用カレンダー（●=利用／予=予約／×=キャンセル）。週別の稼働率・キャンセル・利用人数を自動集計 |
| `12_月次_営業行動` | 5チャネル×日別の接点件数。週別の接点件数を自動集計 |
| `13_月次_加算要件` | 夜勤職員加配の日別配置（週別取得率を自動計算）、重度障害者支援体制の計画・記録チェック、福祉専門職員配置等加算の常勤比率・有資格者比率 |
| `14_案件管理台帳` | 1案件1行。発掘／見学／体験／実調／契約／入居の各日付を列で保持し、停滞14日超を赤表示 |
| `15_KPI累積ログ` | 月締めで週次KPIが「値」で積み上がる保管庫。対象月を切り替えても過去実績が消えない |
| `16_年間推移` | 15の累積ログを月別に集計した年間推移（率は週平均、件数は月合計） |

### 施設担当一覧をどう組み込んだか

- 施設名・担当AMは全シートでプルダウン選択。異動や新規開設は `01_施設マスタ` の1か所を直せば全シートに反映されます。
- 施設IDを主キーにしたので、注記にあった名称差（信中島／小信中島、香江／春近、鳥田／島田）は名称を属性として直すだけで済み、過去データとの突合が切れません。
- `06_ダッシュボード` の担当AM別ブロックで、誰の担当施設に遅延課題が偏っているかが会議前に把握できます。

## 5. 月次シート（入居者データ）の扱い

旧ファイルの月シート22枚は、単なる過去ログではなく**原簿（入力層）**です。ここに入る
利用者ごとの日別稼働、SS予約、営業行動の日別件数、案件の進捗、夜勤加配の配置日、
加算要件のチェックがすべての集計の元になっており、`週間PDCA` に出ている
「■稼働回数：63/56」等の文章も、月シートのセルを `BF16 = BD15&BE7&BD16&…` のように
連結して自動生成されたものです。

したがって**不要ではなく、テンプレートに必ず必要な層**です。初版で欠けていたため、
`10`〜`14` として作り直しました。旧構造との違いは次の3点です。

1. **月ごとにシートを増やさない。** 日付列は `03_設定` の年・月から自動生成され、
   月末日を超える列は自動的に空になります（28日／30日／31日を自動判定）。
2. **入力面と管理面を分離。** 原簿は10〜14、判断はPDCA側（04〜06）。
   週別集計値だけが `05_週次KPIログ` に自動で流れ、二重入力が起きません。
3. **案件はマトリクスから台帳へ。** 日別セルに記号を置く方式をやめ、
   1案件1行＋フェーズごとの日付列にしたため、発掘→契約のリードタイムや
   停滞案件が測れるようになりました。

### 個人情報の扱い

利用者名の列は「利用者ID」を主にし、氏名は任意入力にしています。旧 `Sheet2`
（居室番号・区分・年齢）のような生データは配布テンプレートには含めません。
40施設分を1ファイルに集約する場合は、氏名列を空のままIDで運用することを推奨します。

## 6. 継続運用：毎月シートを増やさない

**「毎月シートを新しく作る」運用は継続できません。** 旧ファイルが実際にそうなっており、
月シートが22枚まで増えた結果、12か月分の列しか持たないHLOOKUP表（`AN24:AY63`）が
26年6月以降のシートを拾えなくなっています。シートを増やす方式は、増やすたびに
集計式の書き換えが必要で、書き換え漏れが `#REF!` や「常に0」として現れます。

改善版では、月末に**締め処理**を1回実行します。ブックの枚数は月に関係なく一定です。

```bash
python tools/pdca/close_month.py 週間PDCA_〇〇_2026年08月.xlsx
```

締め処理が行うこと:

1. **当月ブックをそのまま保管**（`〇〇_実績.xlsx`）。日別の入力も数式も残るので、
   後から「8月の誰がいつ入院したか」を確認できます。以後このファイルは編集しません。
2. **週次KPIを `15_KPI累積ログ` へ値で追記**。数式ではなく値なので、対象月を切り替えても
   過去の実績が書き換わりません。同じ施設・同じ年月が既にある場合は二重登録を拒否します。
3. **翌月ブックを生成**。日別入力欄（GH稼働・SS稼働・営業行動・夜勤加配・体制加算チェック）を
   空にし、`03_設定` の対象年月を1つ進めます。利用者名・職員名・課題管理表・案件管理台帳は
   引き継がれるため、翌月に転記する作業は発生しません。

年度をまたぐ推移は `16_年間推移`（15の累積ログを月別集計）で見ます。
40施設を横断したい場合は、各施設の `15_KPI累積ログ` を縦に連結すればそのまま集計できます。

> 締め処理の前に必ずExcelで開いて保存してください。数式の計算結果（キャッシュ値）を
> 読み取って累積ログに書き込むため、Excelを一度も通していないブックでは実績が空のまま追記されます。

## 7. 移行の進め方（案）

1. 1施設で1か月試行し、`05_週次KPIログ` の指標セット（現在9指標）を実運用に合わせて調整する。
2. 指標が固まったら40施設へ展開。月シートを増やす運用はやめ、年・月列で蓄積する。
3. 旧ファイルの過去実績は、必要な指標だけを `05_週次KPIログ` の形に流し込む（月次の集計値でよい）。
4. 個人データ（旧 `Sheet2`）はテンプレートに含めず、別ファイルで管理する。

## 8. 再生成

```bash
pip install openpyxl
python tools/pdca/build_pdca_template.py \
  --facility-master tools/pdca/facility_master_source.xlsx \
  --out dist/週間PDCA_改善版テンプレート.xlsx
```

月締め:

```bash
python tools/pdca/close_month.py <当月のブック> [--out-dir <出力先>]
```
