# シフト・勤怠CSV・タイミー明細 照合ツール

勤務表Excel（管理用シート／マスタ設定）を基準に、タイムカード実績CSV・タイミー利用明細CSV とのズレを確認するブラウザ単体ツールです。`index.html` をブラウザで開くだけで動きます。データは端末外に送信されません。

## 使い方

1. `index.html` をブラウザで開く
2. 勤務表Excel・タイムカード実績CSV（・タイミー利用明細CSV）を選ぶ
3. 「比較実行」

結果は6つのタブに出ます。

| タブ | 内容 |
|---|---|
| 日別ズレ | 予定シフトと打刻の差（打刻漏れ・時刻ズレ・休みなのに打刻あり） |
| 月間集計 | 勤務表CU列の予定時間と、打刻から概算した実績時間の差 |
| タイミー枠数 | **日付 × 区分（日勤／夜勤）でのシフト枠数と明細件数の突合** |
| タイミー明細照合 | 枠と明細を1対1で突き合わせた開始・終了・実働の差 |
| 未登録シフト | マスタ設定に無いシフト記号、数式エラーセル |
| 警告 | ファイル・列・日付の問題（従来は無警告で捨てていたもの） |

## タイミー照合の考え方

シフト表のタイミー枠は匿名（「タイミー日①」「タイミー夜」など）で、明細側はワーカーの実名です。**両者を結ぶキーは存在しないため、どのワーカーがどの枠かの特定はできません。** その代わり2段構えで差異を出します。

- **レベル1（タイミー枠数タブ）** — 日付 × 区分で「枠 n件 / 明細 m件 / 過不足 ±k」。個人の特定が不要なので確実に出せます。
- **レベル2（タイミー明細照合タブ）** — 同じ日付・区分の中だけで開始時刻の近い順に1対1で対応させ、開始差・終了差・実働差を出します。

夜勤は「入り＋翌日の明け」を1サイクルとして扱います（例：深夜 2.0h + 深夜明 4.0h = 6.0h が明細の実働6.0hに対応）。

個人まで特定したい場合は、タイミー管理画面の **「管理用ラベル」に枠名を入れる運用** が必要です。ラベルが入っていれば完全な1対1照合ができます。

## 設定

| 設定 | 既定 | 説明 |
|---|---|---|
| 時刻ズレ許容範囲 | 15分 | 予定時刻と打刻・QR時刻の差の許容 |
| 月間・実働時間差の許容範囲 | 0.25時間 | 月間集計とタイミー実働差の許容 |
| 「派遣」行もタイミー照合の枠として数える | ON | 下記参照 |
| 月をまたぐ夜勤を月末24:00で分割 | ON | 勤務表の「末◯◯」「初◯◯」に合わせる |
| 店舗ID → 施設名 対応表 | 空 | 明細の `管理用店舗ID` から施設を決める |

### 「派遣」行の扱い

勤務表の「氏名（派遣）」行は、施設によってタイミーの枠として使われていることがあります。日別ズレ・月間集計からは常に除外（タイムカードに現れないため）しつつ、タイミー照合の枠としては数えるかどうかを設定で切り替えられます。

タイミー枠数タブには `うちタイミー` `うち派遣` `過不足(派遣除く)` を併記しているので、**設定を変えて再実行しなくても両方の読み方ができます。**

## 検証

```
node verify.js                                              # ユニットテスト（依存なし）
npm install xlsx
node verify.js <勤務表.xlsx> <勤怠.csv> [<タイミー明細.csv>]   # 実ファイルで結果を確認
```

`verify.js` は `index.html` の `<script>` からロジック部分だけを取り出して実行します。画面まわりは `document` が未定義のときスキップされるため、HTMLを分割せずにテストできます。

## 既知の制約

- Excelの列位置（B=職種／M=氏名／AE=勤務形態／AI列から2列おきに日付／CU=月間時間）とマスタ設定の行範囲（11〜113行）は固定です。勤務表のフォーマットが変わると動きません。
- 勤務表の同一氏名が複数行ある場合、CU列（月間時間）は単純合算されます。上限チェックはしていません。
- 夜勤の予定日と実打刻日が1日ずれている場合、「入り側で打刻なし」と「翌日は空欄なのに打刻あり」の2件に分かれて報告されます。
- 月間集計の許容範囲（既定0.25時間）は実データに対して厳しく、ほぼ全員が要確認になります。運用に合わせた調整が必要です。

## 変更履歴

### v2.15

タイミー照合（A群）、日別・月間（B群）、無警告で壊れる箇所（C群）を修正。

**A群 — タイミー照合**

| # | 内容 |
|---|---|
| A-1 | 「派遣」を含む行を完全除外していたため照合の分母が半減していた。日別・月間からは除外しつつ枠としては数える |
| A-2 | 夜勤を「入り」コマ単体で比較していた。入り＋翌日の明けを1サイクルに畳む |
| A-3 | 日勤／夜勤の区分を無視して日付だけで総当たりしていた。(日付×区分) で束ねる |
| A-4 | ペアリング用スコアが日跨ぎ非対応だった（表示用だけ対応済みで不整合）。`timeDiffMin` に統一 |
| A-5 | `hourTolerance` を受け取るだけで使っていなかった。実働差の判定に使う |
| A-6 | 前月・翌月の明細が混ざっても除外していなかった。勤務表の年月で絞る |
| A-7 | 施設をファイル名からしか推測していなかった。`管理用店舗ID`・求人タイトルを優先。突合は施設グループ単位で行い、食い違いは警告に出す |
| A-8 | タイミー枠の判定が氏名の「タイミー」文字列依存だった。区分はシフト記号（マスタ）で決める |

**B群 — 日別・月間**

| # | 内容 |
|---|---|
| B-1 | コメントの休憩表記「1h」「深夜2h」を控除できなかった（「時間」表記のみ対応していた） |
| B-2 | 旧字体・異体字（髙/高、﨑/崎、邊/辺 など）で同一人物が別人に分裂していた |
| B-3 | 終了0:00の夜勤（深夜・末深夜）が日勤と誤判定され、夜勤入りの日に退勤打刻を要求していた |
| B-4 | タイミー枠・派遣枠の予定時間が職員として月間集計に混入していた |
| B-5 | 月初の夜勤明けが実績から欠落していた（月末側だけ救済されていた）。月末24:00で分割して両方計上する |
| B-6 | 氏名末尾の数字・丸数字を無条件に削除し、別人・別枠を統合していた。括弧付き連番のみ削除する |
| B-7 | 勤怠CSVを勤務表の年月で絞っていなかった。複数月のCSVで前月分が全件ノイズになっていた |
| B-8 | `getMaster` のあいまい一致が緩く、「早」が「早番」の時刻を拾うなど別シフトの時刻を返すことがあった |
| B-9 | 常に31日分の列を読み、2月などで存在しない日付（2/30）を生成していた |
| B-10 | 同一人物設定が推移的に効かなかった（`A=B` と `B=C` を別行に書くと行順で結果が変わる）。Union-Find に変更 |

**C群 — 無警告で壊れる箇所**

| # | 内容 |
|---|---|
| C-1 | CSVヘッダ名が違うと全行ドロップして「全員打刻なし」になっていた。必須列を検証してエラーにする |
| C-2 | 日付を解釈できない行を無警告で捨てていた。件数を警告に出す |
| C-3 | どのExcelにも紐づかないCSVを無警告で捨てていた。警告に出す。`【タイミー】` を施設名と誤認しないようにした |
| C-4 | 同じファイルを複数回選ぶと二重計上していた。重複を除去する |
| C-5 | Excel1枚の読み込み失敗で全施設の処理が止まっていた。施設単位で継続する |
| C-6 | 数式エラーセル（#REF! など）は `sheet_to_json` が空文字で返すため、**空欄＝休みとして黙って消えていた**。空欄判定より先に検出して別カテゴリで報告する |
| C-7 | ファイル名からの年月推定が4桁の数字なら何でも拾っていた。妥当性を検証し、駄目ならシートの年月を使う |
