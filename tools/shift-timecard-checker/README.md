# シフト・勤怠CSV・タイミー明細 照合ツール

勤務表Excel（管理用シート／マスタ設定）を基準に、タイムカード実績CSV・タイミー利用明細CSV とのズレを確認するブラウザ単体ツールです。`index.html` をブラウザで開くだけで動きます。データは端末外に送信されません。

## 使い方

1. `index.html` をブラウザで開く（`xlsx.full.min.js` を同じ場所に置いておくとオフラインでも動きます）
2. 勤務表Excel・タイムカード実績CSV（・タイミー利用明細CSV）を選ぶ
3. 「比較実行」

結果は6つのタブに出ます。

| タブ | 内容 |
|---|---|
| 日別ズレ | 予定シフトと打刻の差（打刻漏れ・時刻ズレ・休みなのに打刻あり） |
| 月間集計 | 勤務表CU列の予定時間と、打刻から概算した実績時間の差 |
| タイミー枠数 | **日付 × 区分（日勤／夜勤）でのシフト枠数と明細件数の突合** |
| タイミー明細照合 | 枠と明細を1対1で突き合わせた開始・終了・実働の差 |
| 未登録シフト | マスタ設定に無いシフト記号・数式エラーセル（シフト単位に集約して件数表示） |
| 警告 | ファイル・列・日付の問題（従来は無警告で捨てていたもの） |

## タイミー照合の考え方

シフト表のタイミー枠は匿名（「タイミー日①」「タイミー夜」など）で、明細側はワーカーの実名です。**両者を結ぶキーは存在しないため、どのワーカーがどの枠かの特定はできません。** その代わり2段構えで差異を出します。

- **レベル1（タイミー枠数タブ）** — 日付 × 区分で「枠 n件 / 明細 m件 / 過不足 ±k」。個人の特定が不要なので確実に出せます。
- **レベル2（タイミー明細照合タブ）** — 同じ日付・区分の中だけで開始時刻の近い順に1対1で対応させ、開始差・終了差・実働差を出します。

夜勤は「入り＋翌日の明け」を1サイクルとして扱います（例：深夜 2.0h + 深夜明 4.0h = 6.0h が明細の実働6.0hに対応）。

個人まで特定したい場合は、タイミー管理画面の **「管理用ラベル」に枠名を入れる運用** が必要です。ラベルが入っていれば完全な1対1照合ができます。

## 設定

| 設定 | 既定 | 説明 |
|---|---|---|
| 遅刻・早退の許容 | 15分 | 予定より**遅い出勤**・**早い退勤** |
| 早出・残業の許容 | 60分 | 予定より**早い出勤**・**遅い退勤** |
| 月間・実働時間差の許容範囲 | 0.25時間 | 月間集計とタイミー実働差の許容 |
| 月間差分の許容率 | 5% | 予定時間に対する割合。時間と率の**緩い方**で判定 |
| 1日の標準所定時間 | 8時間 | 「有4」などが部分有給か終日休みかの判定に使う |
| 「派遣」行もタイミー照合の枠として数える | ON | 下記参照 |
| 月をまたぐ夜勤を月末24:00で分割 | ON | 勤務表の「末◯◯」「初◯◯」に合わせる |
| 予定と実績の「1日ずれ」を1件にまとめる | ON | 下記参照 |
| 店舗ID → 施設名 対応表 | 空 | 明細の `管理用店舗ID` から施設を決める |

### 早出・残業と遅刻・早退を分ける理由

現場では予定より早く出勤し、遅く退勤するのが常態です。両方を同じ15分で見ると日別ズレが「出勤16分早い」「退勤16分遅い」で埋まり、本当に見たい遅刻・欠勤が埋もれます。方向によって許容を分けることで、実データでは日別ズレが 292件 → 222件になりました（大きな乖離は残ります）。

### 「1日ずれ」の集約

夜勤の予定日と実際の入り日が1日ずれていると、「予定日に打刻なし」と「隣の日は空欄なのに打刻あり」の2件に分かれます。同一人物で隣り合う日にあり、かつ**不足している打刻の種類が一致する**場合（明け＝退勤が無い予定 ↔ 退勤打刻のある日）に限って1件の「日ずれ」にまとめます。

### 月間集計の読み方

差分だけでは原因が分からないため、`予定勤務日数` と `実績打刻日数` を並べています。日数が3日以上食い違う場合は内容欄にその旨を出します。実データでは次のように原因が一目で分かります。

```
遠藤　貴之    予定CU 293h / 予定27日   実績 53.3h / 打刻9日    ← 予定27日 / 打刻9日 と日数が食い違っています
五十嵐　汐里  予定CU  26h / 予定 4日   実績132.2h / 打刻20日   ← 予定4日 / 打刻20日 と日数が食い違っています
```

### 「派遣」行の扱い

勤務表の「氏名（派遣）」行は、施設によってタイミーの枠として使われていることがあります。日別ズレ・月間集計からは常に除外（タイムカードに現れないため）しつつ、タイミー照合の枠としては数えるかどうかを設定で切り替えられます。

タイミー枠数タブには `うちタイミー` `うち派遣` `過不足(派遣除く)` を併記しているので、**設定を変えて再実行しなくても両方の読み方ができます。**

## 検証

```
node verify.js                                              # ユニットテスト（依存なし）
npm install xlsx
node verify.js <勤務表.xlsx> <勤怠.csv> [<タイミー明細.csv>]   # 実ファイルで結果を確認
```

`verify.js` は `index.html` の `<script id="tool-logic">` からロジック部分だけを取り出して実行します。画面まわりは `document` が未定義のときスキップされるため、HTMLを分割せずにテストできます。

## 既知の制約

- Excelの列位置は見出し（「氏名」「職種」「開始」「終了」）から自動検出しますが、見出しが無いレイアウトでは既定値（B=職種／M=氏名／AE=勤務形態／AI列から2列おきに日付／CU=月間時間、マスタは11〜113行）にフォールバックします。既定と違う位置を検出したときは警告に出ます。
- 勤務表の同一氏名が複数行ある場合、CU列（月間時間）は単純合算されます。上限チェックはしていません（実データに月293時間の例あり）。
- タイミー照合で「どのワーカーがどの枠か」の特定はできません（前述）。
- CSVのダウンロード名はASCIIです。ブラウザが `download` 属性の非ASCII文字を無視し、拡張子なしの「download」で保存されてしまうためです。

## 同梱ライブラリ

`xlsx.full.min.js` は SheetJS (js-xlsx) 0.18.5 / Apache-2.0 です。npm パッケージ `xlsx@0.18.5` の `dist/xlsx.full.min.js` をそのまま置いています。

```
sha384-vtjasyidUo0kW94K5MXDXntzOJpQgBKXmE7e2Ga4LG0skTTLeBi97eFAXsqewJjw
```

CDN の `integrity` は指定していません。配信元のハッシュを実物で検証できないまま推測値を書くと、読み込み自体が失敗して `XLSX` が未定義になるためです（v2.15 で実際に発生させてしまいました）。ローカルに置く方式であれば CDN に依存しません。

**D群 — 判定基準**

| # | 内容 |
