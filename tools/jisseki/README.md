# 実績記録表 セル抽出ツール

Dropbox 上の実績記録表（GH 1F/2F・短期）から請求用の数値を抽出して集計する。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `jisseki_common.py` | フォルダ走査・ファイル種別判定・年月判定などの共通処理 |
| `jisseki_cell_extract.py` | 本体。セル抽出と集計を行い Excel を出力する |
| `jisseki_file_check.py` | 事前確認用。どのファイルが対象になるかだけを出力する |
| `test_jisseki.py` | 回帰テスト |
| `実績記録表_抽出.bat` | 抽出の実行用（Shift_JIS 保存） |
| `実績記録表_ファイル確認.bat` | 事前確認の実行用（Shift_JIS 保存） |

判定ロジックは `jisseki_common.py` に集約している。確認ツールと抽出ツールで
「片方だけファイルを見つける」という食い違いが起きないようにするため、
判定を変えるときは必ずこのファイルを直す。

## 実行

```
pip install pandas openpyxl
```

`実績記録表_抽出.bat` をダブルクリックする。または:

```
py jisseki_cell_extract.py
```

テスト:

```
py -m unittest test_jisseki -v
```

## 設定箇所

`jisseki_common.py`

- `BASE_DIR` … 実績記録表の保存先
- `OUTPUT_DIR` … 出力先
- `EXCLUDE_FOLDER_KEYWORDS` … 走査しないフォルダ（テストフォルダ等）
- `EXCLUDE_SHEET_NAMES` / `EXCLUDE_SHEET_KEYWORDS` … 利用者シートではないシート
- `FACILITY_NAME_RULES` … 施設名の正規化

`jisseki_cell_extract.py`

- `GH_TOTAL_ROW` / `SS_TOTAL_ROW` … 合計行。日次データの行範囲はここから逆算する
- `GH_USER_NAME_CELL` / `SS_USER_NAME_CELL` … 利用者名セル（後述）

## 出力シート

| シート | 内容 |
|---|---|
| GH_利用者別明細 | GH の利用者ごとの抽出値 |
| GH_施設別集計 | 施設ごとの合計と利用者数 |
| GH_入退居状況集計 | C列の状況別の日数 |
| GH_加算集計 | 加算ごとの**該当**人数（「非該当」「なし」は含めない） |
| GH_加算内訳 | 加算の区分値ごとの人数（人員配置体制加算のⅠ/Ⅱ/Ⅴ別など） |
| GH_住居外利用_利用者別 | **誰に何回**住居外利用がついているか（0回の人は載せない） |
| GH_住居外利用_施設別 | **施設ごとに何回**あったか、該当人数、利用者数 |
| GH_E列値内訳 | E列の日次範囲に実際に入っている値と件数（表記確認用） |
| 短期_利用者別明細 | 短期の利用者ごとの抽出値 |
| 短期_施設別集計 | 施設ごとの合計と利用者数 |
| エラー一覧 | 読み取れなかったもの・要確認のもの |
| スキップシート一覧 | 集計から外したシートと、その理由 |

**スキップシート一覧は毎回確認すること。** 実在の利用者が誤って除外されていないか、
ここで検証できるようにしている。

## レビューで直した内容

### 住居外利用（E列）

`E40` がそのシートの住居外利用の総数。以前は E列を一切読んでおらず、
住居外利用は誰の分も集計されていなかった。以下を追加した。

- `GH_利用者別明細` に `住居外利用` 列（E40 の値）
- `GH_施設別集計` の合計対象に `住居外利用` を追加
- `GH_住居外利用_利用者別` / `GH_住居外利用_施設別` の2シート
- 突き合わせ用に `住居外利用_日次入力数`（E9:E39 の入力数）を併記。
  合計セルが数式のまま値を持たない場合に 0 と誤読するのを検知できる。
  `合計と日次の照合` 列が「要確認」になっていたら中身を見ること。

### 数値が誤っていた点

1. **テンプレート／非利用者シートが利用者として集計されていた**
   `実績記録票` `延べ日数` `算定項目リスト` `重度障害者支援加算要件` `空き部屋◯◯` を除外。
   2026年4月の抽出結果では GH明細1062行のうち290行が架空の利用者で、
   基本算定日数が全社で1,175日過大（20/43施設に影響）だった。

2. **加算集計の「入力あり人数」が全件カウントになっていた**
   空欄判定だったため「非該当」「なし」も入力ありとして数えられ、
   全施設で `該当人数 == 利用者数` になっていた。`is_applicable()` で
   非該当表記を除外し、区分値ごとの内訳シートを追加した。

3. **列全体を走査していたため表外のセルを数えていた**
   日次データの行範囲（GH: 9〜39行 / 短期: 7〜37行）に限定。
   「算定項目リスト」シートの選択肢を拾って併給回数が38回過大になっていた。

### 取りこぼし・誤選択

4. **1月指定で10〜12月、2月指定で12月のファイルを拾っていた**
   `"1月" in "11月"` が真になる、`"2026-1"` が `"2026-10"` の前方一致になる、が原因。
   数字境界つきの正規表現に変更した（`test_jisseki.py` に回帰テストあり）。

5. **候補ファイルが複数あっても無警告で更新日時が最新のものを採用していた**
   Dropbox の同期で mtime が書き換わると古い月を掴む。月指定モードでは
   ファイル名の年月を優先し、複数候補があればエラー一覧に出すようにした。

6. **対象年月の検証がなかった**
   ファイル名から年月を検出して `検出年月` 列に出す。
   指定月と不一致、または「最新」モードで年月が混在する場合は警告する。

7. **テストフォルダを走査していた**

8. **様式ずれを検知できなかった**
   合計行が存在しないシート、当月日数を超える算定日数のシートは
   集計から外してエラー一覧に出す。

9. **`to_number()` が異常値を黙って0にしていた**
   `"1,234"` が0になる、全角数字が読めない、などを修正。
   変換できない値はエラー一覧に記録する。

### 整合性・保守性

10. 2スクリプトで `get_file_type()` の判定がズレていた（`1Ｆ` のような半角数字＋全角Ｆを
    確認ツールだけ取りこぼす）。共通化し、全角半角の4通りすべてを正規化して判定する。
11. 確認ツールも `normalize_facility_name()` を通すようにし、抽出結果と突合できるようにした。
12. エラー一覧の列を固定した（以前はファイル単位とシート単位でキーが違い列順が変わった）。
13. 施設名の正規化で複数フォルダが同名に潰れる場合に警告を出す。
14. `wb.sheetnames` ではなく `wb.worksheets` を使う（チャートシートで落ちない）。
15. `input()` の EOF、年の範囲外入力に対応。
16. 出力先が Excel で開かれている場合は別名保存にフォールバック。
17. 必要な範囲だけを一度に読む方式に変更し、`read_only` で開けるようにした。
18. 短期支給量の文字列（`短期入所　１４日/月` など）から日数を取り出す
    `短期支給量(日)` 列を追加。

### バッチファイル

- Shift_JIS で保存し `chcp 932` を指定（UTF-8 保存だと日本語が化ける）
- Python の終了コードを見て、失敗時に「完了しました」と表示しないようにした
- `py` が無い場合のメッセージを追加
- `%~dp0` でバッチと同じフォルダに移動（`jisseki_common.py` を import するため）

## GH シートの実レイアウト（サンプルで確認済み）

RASIEL 1F/2F 2026年7月分（Ver.202606）で確認した配置。

| セル | 内容 |
|---|---|
| I2 | 支給決定障害者等氏名（`GH_USER_NAME_CELL`） |
| P2 | 支援区分（`GH_BAND_CELL`。O2 が見出し） |
| E3 / I3 / M3 / Q3 | 重度障害者支援加算(Ⅰ)(Ⅱ) / 人員配置体制加算 / 福祉専門職員配置等加算 |
| E4 / I4 / M4 / Q4 | 強度行動障害者地域移行体制特別加算 / 同体験利用加算 / ピアサポート実施加算 / 感染対策向上加算 |
| 7〜8行目 | 見出し（C8=サービス提供の状況、E8=住居外利用） |
| 9〜39行目 | 日次データ（31日分） |
| 40行目 | 合計（C=基本算定日数、E=住居外利用、F=夜勤職員加配加算、I=医療連携体制加算(Ⅶ)、J〜O=各加算） |
| 42行目 | 合計行の見出し |

- テンプレートの `実績記録票` シートは I2 が空欄なので、シート名の除外に加えて
  氏名セルでも弾ける（二重に防いでいる）。
- G列・H列（入院時支援加算・帰宅時支援加算）は合計セルが無いため、
  日次範囲の○を数えている。
- `強行地域移行加算` `強行体験利用加算` は実際には
  `強度行動障害者地域移行体制特別加算` `強度行動障害者体験利用加算`。
  列名は既存の出力に合わせてそのままにしてある。変えるなら
  `GH_ADDON_FLAG_COLUMNS` を直す。

## 未確認（短期のみ）

短期のサンプルが未入手のため、以下は従来コードの前提のまま。

- 合計行を 38行目、日次を 7〜37行目としている
  （`SS_TOTAL_ROW` / `DAY_ROW_COUNT` で調整）

  短期のファイルを1つもらえれば GH と同じように確定できる。
